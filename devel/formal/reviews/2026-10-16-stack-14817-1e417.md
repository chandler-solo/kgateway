## Findings

### P1 — Reconnect clearing is not serialized with publication

[proxy_syncer.go:291–305](https://github.com/kgateway-dev/kgateway/blob/1e417af796a241a6aa286a240fe7855d1fab56da/pkg/kgateway/proxy_syncer/proxy_syncer.go#L291-L305)
clears the cache in the admitting callback, then takes the gate lock separately
in the admitted callback. Stream admission excludes other admissions during the
clear, but it does not exclude an already running publisher.

The new probe uses the real unique-client callbacks and SnapshotCache:

1. An old-connection `syncXds` holds the gate lock and pauses immediately before
   cache installation.
2. The old stream closes; its replacement's admitting hook clears the cache.
3. The old publisher resumes and installs `old-on-A` after that clear.
4. The admitted hook resets gate bookkeeping and offers the current deferred
   candidate, which remains pending.
5. A fresh RDS watch nevertheless receives `old-on-A` instead of waiting.

**Evidence: executed Go/cache counterexample**, including three repetitions with
the race detector and no data-race report. This is a locking/protocol ordering
bug; data-race freedom does not exclude it. It affects ALL as well as REFERENCED
mode. The earlier serial hook scenario now passes, so the new hook is a real
improvement, but it is not a complete fence.

The response can replace configuration accepted from another controller; that
application consequence is supported by the old runtime mechanism, but has not
been remeasured on this tip. The new-tip assertion is specifically that the real
cache answers the new connection with the old publication.

**Change:** make connection generation, publisher eligibility and watch
admission one coordinated protocol. Reject an obsolete publisher's installation
and queued response, or serialize the entire transition before admitting
watches. Simply taking `gate.mu` while holding `stateLock` would invert the
reclaimer's existing lock order. Simply clearing again after admission can drop
another newly admitted stream's watches. Include shared-key streams in the
design: the new hook runs only on the key's zero-to-one stream transition.

### P1 — kgw-ent cannot adopt this stack by changing the dependency alone

Downstream [internal/setup/setup.go:349](/Users/davidchandler/gg_reviewing-14184-and-13586-stack/internal/setup/setup.go:349)
still passes seven arguments to the new nine-argument `NewControlPlane`.
The scratch dependency-only build fails at that call. This is a downstream
adoption blocker, not an upstream package compilation failure.

The copied downstream callback implementation also lacks all four contracts:
`HasPriorXDSVersion`, `HasColdStreamSince`, `RunIfDisconnected` and now
`SetConnectionStartHooks`. Its setup does not supply `XDSClientState`.
Changing the constructor call alone therefore does not integrate warm/cold
classification, safe reclaim or the reconnect hook. A nil-state warning is
diagnostic, not integration.

**Evidence: executed downstream compilation and four compile-time interface
failures, plus source wiring inspection.** Existing tests in xdsclients,
peering_outbound, enterprisekgatewaydestinationselector, gateway_parameters and
cmd/sds pass: 64 top-level / 137 total cases. They do not test this missing
integration. The image Make target compiled Go with Docker/Rust outputs omitted;
this is not a successful image build.

**Change:** port and wire the lifecycle contracts and both watch-policy settings
while preserving authenticated Gateway-role resolution, identity-drift handling,
bootstrap-local-cluster capability aggregation and Delta rejection. Do not
replace the downstream callback implementation wholesale with upstream's.

### P2 — Dereference expiry releases an active reference-ahead hold

[dereference_grace.go:189–203](https://github.com/kgateway-dev/kgateway/blob/1e417af796a241a6aa286a240fe7855d1fab56da/pkg/kgateway/proxy_syncer/dereference_grace.go#L189-L203)
notices that a flip is pending, then passes only `holdFlips=true` to
`resolveDeferredPerCluster`. That helper holds only when it finds unready
references. A coherent candidate held solely for reference-ahead has none, so
the prune publishes its new routing types immediately.

**Evidence: executed Go/cache counterexample with a natural timer.** With a
20 ms dereference grace and a one-hour reference-ahead interval, old routing is
initially held. The actual prune callback changes RDS to the new revision after
approximately 20 ms while `pendingFlips` remains active. Three race-enabled
repetitions reproduce it. The old underived-cluster prune regression now passes;
it does not cover this distinct hold reason.

This requires REFERENCED mode. Different configured interval lengths reproduce
it directly; an older removal window overlapping a later addition can also
expire first. The practical concern is routing ahead of cluster availability,
but no live 503 was measured for this schedule.

**Change:** use the same complete hold decision in every publication path,
including prune. Preserve both routing types and their dependency closure until
the applicable release transition, rather than treating an unready-reference
flag as the entire hold state.

### P2 — The carry age bound has no wakeup on quiescent inputs

[publish_gate.go:1038–1095](https://github.com/kgateway-dev/kgateway/blob/1e417af796a241a6aa286a240fe7855d1fab56da/pkg/kgateway/proxy_syncer/publish_gate.go#L1038-L1095)
records `carriedSince` and checks it when another resolver invocation occurs.
It does not schedule expiry. If the only gap is an already referenced missing
cluster, that cluster is carried and routing publishes without a pending flip.
With no later candidate there is no event that enforces the advertised bound.

**Evidence: source inspection plus executed Go/cache counterexample.** With
transition graces disabled, a 20 ms carry bound and no subsequent input, the
cluster is still installed after 300 ms. This finite observation alone is not
a temporal proof; the source has no scheduled transition that can remove it.
The stack's new test sleeps past the bound and then explicitly publishes a
third candidate, which misses this case. The issue also applies in ALL mode.

Stale backend configuration and addresses can consequently persist after the
configured ten-minute default. Address reuse is a possible consequence, not an
observed traffic or security incident in this review.

**Change:** arm an expiry for the earliest carried-cluster deadline, retaining
the latest candidate and generation. On expiry, remove the cluster and its
eligible CLA together. Check that grace/held-closure paths cannot immediately
reintroduce expired carry, and that cancellation cannot replay an older build.

### P3 — Plugin claims still widen unrelated gateways' emitted sets

[emission_filter.go:38–54](https://github.com/kgateway-dev/kgateway/blob/1e417af796a241a6aa286a240fe7855d1fab56da/pkg/kgateway/proxy_syncer/emission_filter.go#L38-L54)
unconditionally consults the global union of claimed names/prefixes. Claim
collection discards the association between a selector and its destinations.
A gateway with no occurrence of that selector therefore retains its claimed
clusters too.

**Evidence: executed Go transformation counterexample.** A `picker` claim for
`tenant-` keeps `tenant-a` alongside `routed` in an unrelated gateway. This
survives the update. Invalid-claim fallback is separately repaired.

The effect is excess CDS/EDS and per-proxy stats cardinality in REFERENCED mode,
not a demonstrated authorization bypass. Neither reviewed tree registers a
built-in `ClaimEmittedClusters` implementation, so this is conditional on an
extension adopting the SDK hook.

**Change:** retain selector-to-destination associations and activate
selector-bound claims only where the selector occurs. Specify unconditional
claims separately if they are needed.

## Remaining coverage and formal work

1. **Connection lifecycle refinement first.** Model separate admission lock,
   gate lock, cache installation, watch creation and response queue events. Add
   this clear/refill schedule as a required counterexample. Specify generation
   validity for publishers and sends, including multiple streams sharing a key,
   delayed KRT deletion, authentication and reclaim. A positive composed runtime
   barrier must work without waiting for the stale response it is meant to
   prevent.
2. **Compose timer reasons and autonomous progress.** Extend the transition
   model with independent unready, reference-ahead, removal and carry-expiry
   deadlines. Require prune to preserve remaining reasons and require carry to
   expire with quiescent input. State timer/transport/KRT fairness separately.
   Reachability of a recovery state is not eventual recovery on every fair run.
3. **Trace the installed/sent/applied boundary.** The stack now correctly keeps
   installation bookkeeping when SetSnapshot installs and then reports a
   fan-out error. This does not retry missed delivery. Preserve the pinned GCP
   repaired parked-watch/unsubscribe behavior and the unrepaired immediate-
   decline and partial-fan-out/no-retry controls. Include new retry-watch
   cancellation, subscription changes, superseding correction and queued-send
   schedules. ACK/NACK events remain separate from independent application
   observations, particularly partial CDS/LDS application on NACK.
4. **Run the real downstream composition.** After adoption wiring, execute the
   actual controller with authenticated mixed warm/cold shared keys, peering
   CDS/EDS changes, enterprise selector/filter dependencies, secrets and
   standalone SDS on standard/FIPS digests. Existing peering unit tests and
   prearmed ServiceEntry sockets do not prove cross-type delivery/application
   order. Exercise natural timers and multiple workers. Run the upstream default
   v1.39.4 image separately; earlier v1.39.1 observations are not evidence for it.
5. **Preserve and strengthen provenance.** Keep source/image/bootstrap identities,
   passing obligations and required counterexamples separate. The October 14
   RF-025 implementation uses row-contribution XOR without protobuf marshaling;
   it is not strict content-idempotence or an injectivity proof. RF-002's derived
   empty CLAs publish; the superseded warm contents gate is only a historical
   control. The EDS-cache/default-timeout correction remains bootstrap-specific,
   not a universal 15-second recovery bound.

No new Lean theorem, larger model bound or existing runtime pass closes the
concrete admission and timer failures above. The next useful milestone is a
corrected candidate that passes these executable obligations, followed by
source-linked lifecycle traces and independent runtime observations.
